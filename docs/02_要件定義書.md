### 1.1 機能要件の詳細（フェーズ1）

#### FR-01 社員証認証
- カードリーダーが IDm を取得し、MEMBER テーブルの `card_idm`（かつ `is_active = true`）と照合する。
- 一致した場合は氏名・社員番号・ロールを取得し、以降の画面へ遷移する。
- 一致しない／無効の場合はエラー画面（S06）を表示し、一定時間後に待機画面へ戻る。
- **受入条件：** 未登録カードで貸出に進めないこと。登録済みカードで正しく本人情報が得られること。

#### FR-02 貸出
- 前提：鍵が空き（`returned_at IS NULL` の LOAN が存在しない）であること。貸出中なら貸出中表示（S/エラー）へ。
- 貸出時間を 15分 / 30分 / 1時間 / 2時間 / 4時間 / 8時間（= 15/30/60/120/240/480 分）から選択させる。
- 選択後、LOAN を登録（`borrowed_at`, `duration_min`, `due_at`）し、解錠する（FR-05）。
- **受入条件：** 貸出中に別の人が貸出に進めないこと。ログに貸出日時・返却予定が残ること。

#### FR-03 返却
- タッチした IDm に対応する「貸出中かつ本人」の LOAN を検索する。
- 該当すれば返却確認画面（S05）を表示し、「返却する」で `returned_at` を記録して解錠する（FR-05）。
- 該当しなければエラー表示する。
- 本人以外の返却可否は運用方針により決定（[10](10_課題・確認事項管理表.md) Q6）。
- **受入条件：** 返却で `returned_at` が記録され、以降その鍵が貸出可能になること。

#### FR-04 貸出状況表示
- 待機画面（S01）に「保管中」または「貸出中（氏名・返却予定時刻）」を表示する。
- 氏名表示の可否は [10](10_課題・確認事項管理表.md) Q4 に従う。

#### FR-05 解錠制御
- GPIO 出力でロック駆動回路を駆動し、ソレノイドへ数秒間のみ通電して解錠する。
- 通電時間は設定値（既定：数秒）。通電後は必ず OFF に戻す（発熱・焼損防止）。
- **受入条件：** 1回の解錠要求で1回だけ通電し、指定秒数後に確実に OFF になること。

#### FR-06 メンバー管理
- 管理メニュー（A01→A02）から、社員証タッチで IDm を取得し、氏名・社員番号・ロールを登録する。
- 既存メンバーの無効化（`is_active = false`）・削除ができる。
- 登録・無効化の権限者は [10](10_課題・確認事項管理表.md) Q3 に従う。

#### FR-07 貸借ログ出力
- 管理メニュー（A01→A03）から期間を指定し、CSV を書き出す（USBメモリ等）。
- 日時書式は `YYYY/MM/DD hh:mm`。項目は帳票と同一。CSV 仕様は [06_データベース設計書](06_データベース設計書.md) 参照。

#### FR-08 管理者認証
- ロールが `admin` の社員証タッチで管理メニュー（A01）に入る。
- `user` では管理メニューに入れない。

#### FR-09 延滞表示
- `returned_at IS NULL` かつ現在時刻 > `due_at` の貸出を、待機画面で強調表示する。

## 2. 非機能要件

| 要件ID | 分類 | 要件 | 根拠・備考 |
|--------|------|------|-----------|
| NFR-01 | 可用性 | 常時のサーバ／ネットワーク接続なしで貸出・返却が動作する（スタンドアロン） | 設置場所のネットワーク未確定（[10] Q8） |
| NFR-02 | 可用性 | 停電・故障時に鍵を取り出す代替手段（予備鍵）を用意する | 運用要件（[10] Q7） |
| NFR-03 | 完全性 | 時刻は NTP で同期する。ネットワークがない場合は RTC を追加しログ日時のずれを防ぐ | P7。Pi は標準で時計用電池を持たない |
| NFR-04 | 完全性 | 貸借ログは追記主体で、過去記録を利用者操作で改変・削除できない | 帳票の代替として追跡性を担保 |
| NFR-05 | ユーザビリティ | タッチスクリーン前提。ボタンは大きく、原則「1画面1操作」 | 指でのタッチ操作 |
| NFR-06 | ユーザビリティ | 無操作が一定時間続いたら待機画面へ自動復帰する | 誤操作・放置対策 |
| NFR-07 | 性能 | 社員証タッチから認証結果表示まで概ね2秒以内 | 現場のストレス低減 |
| NFR-08 | 安全性 | 解錠通電は数秒で自動 OFF とし、コイルの過熱を防ぐ | P2 |
| NFR-09 | セキュリティ | 利用は登録メンバーに限定。管理機能は管理者ロールに限定 | BR-2 |
| NFR-10 | セキュリティ / プライバシー | 画面への氏名表示範囲、ログ閲覧権限、保管期間を定める | [10] Q4, Q9 |
| NFR-11 | 保守性 | データ設計は複数物品を見越した構造とし、将来の作り直しを避ける | P6, BR-8 |
| NFR-12 | 移行性 | 出力 CSV は既存帳票と同項目・同書式とし、移行コストを抑える | P5, BR-6 |
| NFR-13 | 運用性 | 解錠通電時間・無操作タイムアウト等は設定で変更可能とする | 現場調整のため |

## 3. 制約条件

| ID | 制約 | 出典 |
|----|------|------|
| CON-1 | ハードウェアは Raspberry Pi / 専用タッチスクリーン / RC-S380 / LE-53 / ロック駆動回路 | D10 |
| CON-2 | 施錠は人手で行い、システムは解錠のみ担当する | D8 |
| CON-3 | 鍵は1本。同時貸出は1件まで | D7, P3 |
| CON-4 | 認証は社員証の IDm のみを用い、カード内部データは読まない | P4 |
| CON-5 | 貸出時間は規定の6種から選択する | D4 |
| CON-6 | 実装言語は Python、GUI は nfcpy + GUI ツールキット、DB は SQLite を想定 | 技術方針 |

## 4. 想定技術スタック（暫定）

| 層 | 技術 | 備考 |
|----|------|------|
| OS | Raspberry Pi OS | 機種・OS は要確定（[10] 参照） |
| 言語 | Python 3 | — |
| カード読取 | nfcpy | RC-S380 で IDm 取得。実機確認要 |
| GUI | タッチ向け GUI（例：Kivy / PyQt / Tkinter） | 解像度に合わせて選定 |
| DB | SQLite | スタンドアロン・単一ファイル |
| GPIO | gpiozero / RPi.GPIO | 解錠制御 |
| 時刻 | systemd-timesyncd（NTP） / RTC | NFR-03 |

## 5. 要件一覧の妥当性（トレース）

- すべての機能要件は 01 のビジネス要求（BR-x）に紐づく。
- フェーズ1要件（FR-01〜09、該当 NFR）で成功基準 SC-1〜SC-4 を満たす。
- 未確定の要件は [10_課題・確認事項管理表](10_課題・確認事項管理表.md) で管理し、回答確定後に本書を改訂する。
