### 1.1 機能要件の詳細（フェーズ1）

#### FR-01 社員証認証
- カードリーダーが IDm を取得し、MEMBER テーブルの `card_idm`（かつ `is_active = true`）と照合する。
- 一致した場合は氏名・社員番号・ロールを取得し、以降の画面へ遷移する。
- 一致しない／無効の場合はエラー画面（S06）を表示し、一定時間後に待機画面へ戻る。
- **受入条件：** 未登録カードで貸出に進めないこと。登録済みカードで正しく本人情報が得られること。

#### FR-02 貸出
- 前提：空いている物品（当該 `item_id` で `returned_at IS NULL` の LOAN が存在しない）が1件以上あること。空きがなければエラー表示へ。
- 空きが複数件あるときは物品選択画面（borrow_item）を表示し、対象物品を選ばせる。空きが1件のみならタッチ回数を増やさず時間選択へ直行する。
- 貸出時間を 15分 / 30分 / 1時間 / 2時間 / 4時間 / 8時間（= 15/30/60/120/240/480 分）から選択させる。
- 選択後、LOAN を登録（`borrowed_at`, `item_id`, `duration_min`, `due_at`）し、解錠する（FR-05）。
- **受入条件：** 貸出中の物品に別の人が貸出に進めないこと。ログに貸出日時・物品・返却予定が残ること。

#### FR-03 返却
- タッチした IDm に対応する「貸出中かつ本人」の LOAN を検索する（本人が複数物品を借りている場合は複数件になり得る）。
- 該当が1件なら返却確認画面（S05）を直接表示する。複数件あるときは返却選択画面（return_select）で対象を選ばせたうえで返却確認画面へ進む。
- 「返却する」で `returned_at` を記録して解錠する（FR-05）。返却確認／返却選択画面には「借りる」ボタンがあり、貸出導線（FR-02）へ切り替えられる。
- 該当しなければエラー表示する。
- 本人以外の返却可否は運用方針により決定（[10](10_課題・確認事項管理表.md) Q6）。
- **受入条件：** 返却で `returned_at` が記録され、以降その物品が貸出可能になること。

#### FR-04 貸出状況表示
- 待機画面（S01）に「保管中」または「貸出中（氏名・返却予定時刻）」を表示する。
- 氏名表示の可否は [10](10_課題・確認事項管理表.md) Q4 に従う。

#### FR-05 解錠制御
- GPIO 出力でロック駆動回路を駆動し、ソレノイドへ数秒間のみ通電して解錠する。
- 通電時間は設定値（既定：数秒）。通電後は必ず OFF に戻す（発熱・焼損防止）。
- **受入条件：** 1回の解錠要求で1回だけ通電し、指定秒数後に確実に OFF になること。

#### FR-06 メンバー管理
- 管理メニュー（A01→A02）から、社員証タッチで IDm を取得し、氏名・社員番号・ロールを登録する。
- 既存メンバーの無効化（`is_active = false`）・再有効化ができる。
- 過去の貸借ログとの整合（NFR-04）のため物理削除は行わず、無効化で代替する（削除機能は保守用途に限定し、画面には出さない）。
- ロール変更・氏名/社員番号の編集・カード再発行は FR-14 を参照。初回導入時（管理者が0人）の管理者登録は FR-13 を参照。
- 登録・無効化の権限者は [10](10_課題・確認事項管理表.md) Q3 に従う（解決：管理者がメンバー管理画面(A02)で行う。初回のみ FR-13 のセットアップ画面／CLIで行う）。

#### FR-07 貸借ログ出力
- 管理メニュー（A01→A03）から期間を指定し、CSV を書き出す（USBメモリ等）。
- 日時書式は `YYYY/MM/DD hh:mm`。項目は帳票と同一。CSV 仕様は [06_データベース設計書](06_データベース設計書.md) 参照。

#### FR-08 管理者認証
- ロールが `admin` の社員証タッチで管理メニュー（A01）に入る。
- `user` では管理メニューに入れない。

#### FR-09 延滞表示
- `returned_at IS NULL` かつ現在時刻 > `due_at` の貸出を、待機画面で強調表示する。

#### FR-11 複数物品対応
- ITEM テーブルは複数行の正式マスタとして扱う（`config.json` の `item_name`/`item_location` は空DB初回起動時の初期シードのみに使う）。
- 待機画面（S01）は全物品の状況一覧（空き／貸出中／延滞）を表示する。
- LoanService は物品単位の API（`status_list()` / `available_items()` / `borrow(member, item_id, duration_min)` / `find_returnable_loans(member)`）で扱い、1人が複数物品を同時に借りられる。
- 錠（GPIO）は現状1本を全物品で共用する（CON-3 は「物品ごとに貸出中は1件まで」の意味に拡張）。増設時に物品ごとの錠を割り当てる拡張は FR-15/05_システム設計書の拡張方針を参照。

#### FR-13 初期管理者登録
- 有効な管理者（`role='admin'` かつ `is_active=1`）が0人のときだけ発動する。管理者が1人でもいれば発動しない。
- standby（待機画面）で未登録カードをタッチすると、専用画面 setup へ遷移し、そのカードを管理者として登録できる。
- 誤タッチ訂正のため、setup 画面では再タッチで取り込むIDmを上書きできる。
- CLI `python main.py --add-admin --idm <IDm> --name <氏名> --employee-no <番号>` でも非対話で登録できる（運用復旧用）。
- サービス層（`register_initial_admin`）は画面側の判定に加えて有効管理者の有無を再検査し、二重に防御する。
- **受入条件：** 管理者が1人もいない状態でのみ setup へ遷移すること。登録後は直接 admin_menu へ進むこと。

#### FR-14 メンバー編集・カード再発行
- メンバー管理（A02）で、既存メンバーのロール変更（user↔admin）、氏名・社員番号の編集ができる。
- カード再発行：対象メンバーを選び、次にタッチしたカードのIDmへ付け替える。重複IDm（他メンバーが既に使用中）はエラーとする。
- 最後の有効な管理者は、無効化・user への降格・削除のいずれもサービス層で拒否する（鶏卵問題の再発防止）。
- **受入条件：** 最後の管理者に対する無効化・降格・削除がすべて拒否されること。

#### FR-15 物品管理
- 物品管理（item_admin）で、物品の追加、名称・保管場所の編集、有効化/無効化ができる。
- 貸出中の物品は無効化できない。有効な物品が0件になる無効化（最後の有効物品）も拒否する。
- **受入条件：** 貸出中または最後の有効物品に対する無効化がすべて拒否されること。

## 2. 非機能要件

| 要件ID | 分類 | 要件 | 根拠・備考 |
|--------|------|------|-----------|
| NFR-01 | 可用性 | 常時のサーバ／ネットワーク接続なしで貸出・返却が動作する（スタンドアロン） | 設置場所のネットワーク未確定（[10] Q8） |
| NFR-02 | 可用性 | 停電・故障時に鍵を取り出す代替手段（予備鍵）を用意する | 運用要件（[10] Q7） |
| NFR-03 | 完全性 | 時刻は NTP で同期する。ネットワークがない場合は RTC を追加しログ日時のずれを防ぐ | P7。Pi は標準で時計用電池を持たない |
| NFR-04 | 完全性 | 貸借ログは追記主体で、過去記録を利用者操作で改変・削除できない | 帳票の代替として追跡性を担保 |
| NFR-05 | ユーザビリティ | タッチスクリーン前提。ボタンは大きく、原則「1画面1操作」 | 指でのタッチ操作 |
| NFR-06 | ユーザビリティ | 無操作が一定時間続いたら待機画面へ自動復帰する | 誤操作・放置対策 |
| NFR-07 | 性能 | 社員証タッチから認証結果表示まで概ね2秒以内 | 現場のストレス低減 |
| NFR-08 | 安全性 | 解錠通電は数秒で自動 OFF とし、コイルの過熱を防ぐ | P2 |
| NFR-09 | セキュリティ | 利用は登録メンバーに限定。管理機能は管理者ロールに限定 | BR-2 |
| NFR-10 | セキュリティ / プライバシー | 画面への氏名表示範囲、ログ閲覧権限、保管期間を定める | [10] Q4, Q9 |
| NFR-11 | 保守性 | データ設計は複数物品を見越した構造とし、将来の作り直しを避ける（実装済み：ITEM複数行対応、FR-11/FR-15） | P6, BR-8 |
| NFR-12 | 移行性 | 出力 CSV は既存帳票と同項目・同書式とし、移行コストを抑える | P5, BR-6 |
| NFR-13 | 運用性 | 解錠通電時間・無操作タイムアウト等は設定で変更可能とする | 現場調整のため |

## 3. 制約条件

| ID | 制約 | 出典 |
|----|------|------|
| CON-1 | ハードウェアは Raspberry Pi / 専用タッチスクリーン / RC-S380 / LE-53 / ロック駆動回路（MOSFET ローサイド方式） | D10 |
| CON-2 | 施錠は人手で行い、システムは解錠のみ担当する | D8 |
| CON-3 | 鍵（錠）は1本。1物品あたり同時貸出は1件まで（複数物品が有効な場合でも錠は全物品で共用） | D7, P3 |
| CON-4 | 認証は社員証の IDm のみを用い、カード内部データは読まない | P4 |
| CON-5 | 貸出時間は規定の6種から選択する | D4 |
| CON-6 | 実装言語は Python、カード読取は nfcpy、UI はローカル Web（http.server + SSE）+ Chromium キオスク、DB は SQLite | 技術方針 |

## 4. 想定技術スタック（暫定）

| 層 | 技術 | 備考 |
|----|------|------|
| OS | Raspberry Pi OS | 機種・OS は要確定（[10] 参照） |
| 言語 | Python 3 | — |
| カード読取 | nfcpy | RC-S380 で IDm 取得。実機確認要 |
| UI | ローカル Web（標準ライブラリ `http.server` + SSE）+ Chromium キオスク表示 | タッチ操作前提（800×480） |

| GPIO | gpiozero / RPi.GPIO | 解錠制御 |
| 時刻 | systemd-timesyncd（NTP） / RTC | NFR-03 |

## 5. 要件一覧の妥当性（トレース）

- すべての機能要件は 01 のビジネス要求（BR-x）に紐づく。
- フェーズ1要件（FR-01〜09、FR-11、FR-13〜15、該当 NFR）で成功基準 SC-1〜SC-4 を満たす。
- 未確定の要件は [10_課題・確認事項管理表](10_課題・確認事項管理表.md) で管理し、回答確定後に本書を改訂する。
