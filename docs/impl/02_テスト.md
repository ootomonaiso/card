# テスト

機能ごとにファイルを分けている。共通セットアップ（インメモリDB・モックデバイス・固定時計）は
[`tests/helpers.py`](../../tests/helpers.py) の `make_ctx()` に集約。

## 実行

```bash
python -m unittest discover -s tests            # 全テスト
python -m unittest tests.test_loan -v           # 個別ファイル
```

> モックロックが解錠ログをコンソールに出すため、Windows端末では文字化けして見えることがある（動作に影響なし）。

## 構成

| ファイル | 対象 | 主なケース |
|----------|------|-----------|
| [`test_auth.py`](../../tests/test_auth.py) | 認証 FR-01 / FR-08 | 未登録拒否・登録済み・admin判定・無効化カード拒否 |
| [`test_loan.py`](../../tests/test_loan.py) | 貸出・返却・延滞 FR-02/03/04/09, CON-3 | due算出・同時貸出ブロック・不正時間・本人/他人返却・延滞 |
| [`test_report.py`](../../tests/test_report.py) | CSV出力 FR-07 | 帳票同項目/書式・期間外除外 |
| [`test_terminal.py`](../../tests/test_terminal.py) | 画面遷移（07 画面設計書） | 起動→待機・未登録→エラー・貸出/返却フロー・管理者/メンバー登録 |

- `test_terminal.py` はサーバ側状態機械 `app/web/terminal.py` を HTTP を介さず直接駆動し、
  カードタッチ→画面遷移を検証する（`on_change` で最新stateを捕捉）。
- デバイスはすべてモック（`devices/mock.py`）。実機（nfcpy / gpiozero）は読み込まないため、
  開発機でも追加インストールなしで全テストが通る。

## カバー範囲

- 業務ロジック（認証・貸出・返却・延滞・CSV）: 単体テストで網羅
- 画面遷移（サーバ側状態機械）: `test_terminal.py` で主要フローを確認
- HTTP/SSE 層・ブラウザ描画: 手動確認（`python main.py --seed` → ブラウザ）
- 実機デバイス（RC-S380読取・GPIO通電）: 単体テスト対象外。実機での結合確認が必要（[`../10_課題・確認事項管理表.md`](../10_課題・確認事項管理表.md) 参照）
