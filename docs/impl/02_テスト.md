# テスト

機能ごとにファイルを分けている。共通セットアップ（インメモリDB・モックデバイス・固定時計）は
[`tests/helpers.py`](../../tests/helpers.py) の `make_ctx()` に集約。

## 実行

```bash
python -m pytest tests/ -q            # 全テスト（108件）
python -m pytest tests/test_loan.py -q   # 個別ファイル
```

`python -m unittest discover -s tests` でも同じテストが実行できる（標準ライブラリの unittest 互換）。

> モックロックが解錠ログをコンソールに出すため、Windows端末では文字化けして見えることがある（動作に影響なし）。

## 構成

| ファイル | 対象 | 主なケース |
|----------|------|-----------|
| [`test_auth.py`](../../tests/test_auth.py) | 認証 FR-01 / FR-08 | 未登録拒否・登録済み・admin判定・無効化カード拒否 |
| [`test_loan.py`](../../tests/test_loan.py) | 貸出・返却・延滞 FR-02/03/04/09/11, CON-3 | due算出・物品ごとの同時貸出ブロック・不正時間・本人/他人返却・延滞 |
| [`test_item.py`](../../tests/test_item.py) | 物品管理 FR-15 | 追加・編集・貸出中/最後の有効物品の無効化拒否・有効化/無効化の往復 |
| [`test_member_admin.py`](../../tests/test_member_admin.py) | 初期管理者登録・ロール変更・編集・再発行・最後の管理者保護 FR-13/14 | 管理者0人判定・初期管理者登録の可否・昇格/降格・最後の管理者の無効化/降格/削除拒否・再発行の重複IDm拒否 |
| [`test_report.py`](../../tests/test_report.py) | CSV出力 FR-07 | 帳票同項目/書式・期間外除外 |
| [`test_terminal.py`](../../tests/test_terminal.py) | 画面遷移（07 画面設計書） | 起動→待機・未登録→エラー/セットアップ・貸出/返却フロー・物品選択/返却選択・管理者/メンバー登録 |
| [`test_cli.py`](../../tests/test_cli.py) | CLI `--add-admin` | サーバを起動せず管理者追加・既存管理者がいても追加可・必須項目欠落/重複IDm拒否 |
| [`test_robustness.py`](../../tests/test_robustness.py) | 設定検証・DB整合性・解錠失敗時の挙動 | 不正config拒否・部分ユニークインデックスでの二重貸出防止・解錠失敗時は記録しない・2回目の返却はno-op |

- `test_terminal.py` はサーバ側状態機械 `app/web/terminal.py` を HTTP を介さず直接駆動し、
  カードタッチ→画面遷移を検証する（`on_change` で最新stateを捕捉）。
- デバイスはすべてモック（`devices/mock.py`）。実機（nfcpy / gpiozero）は読み込まないため、
  開発機でも追加インストールなしで全テストが通る。

## カバー範囲

- 業務ロジック（認証・貸出・返却・延滞・CSV・物品管理・メンバー管理・初期管理者登録）: 単体テストで網羅
- 画面遷移（サーバ側状態機械）: `test_terminal.py` で主要フロー（複数物品時の物品選択/返却選択、初回セットアップを含む）を確認
- HTTP/SSE 層・ブラウザ描画: 手動確認（`python main.py --seed` → ブラウザ）
- 実機デバイス（RC-S380読取・GPIO通電）: 単体テスト対象外。実機での結合確認が必要（[`../10_課題・確認事項管理表.md`](../10_課題・確認事項管理表.md) 参照）
