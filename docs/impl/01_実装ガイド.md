# 実装ガイド

対象機: **Raspberry Pi 4 / Raspberry Pi OS Bookworm / Python 3.11**。
開発機（Windows 等）ではデバイスをモックして同じコードが動く。

UI は **ローカルWebアプリ**（標準ライブラリ `http.server` + SSE、追加依存なし）。
Pi 上では Chromium をキオスク表示して使う。

## 1. アーキテクチャ

```
[Raspberry Pi]
  カードリーダー(nfcpy) ─┐
  GPIOロック(gpiozero) ──┤  app/services（UI非依存・無改修）
                         ↓
  app/web/server.py (http.server, 127.0.0.1:8000)
        │   ▲
   SSE  │   │ fetch POST /api/action（操作）
  (push)▼   │
  Chromium --kiosk http://localhost:8000/   ← タッチスクリーン
```

- カードタッチはリーダースレッド → `Terminal`（状態機械）→ **SSEでブラウザへpush**（ポーリング不要・NFR-07）。
- 画面遷移の判断はすべて **サーバ側 `Terminal`** に集約。ブラウザは状態を描画するだけの薄い作り。
- 無操作タイムアウト(NFR-06)・解錠後の自動復帰はサーバ側タイマ。
- マルチスレッド化に伴い、DBアクセスは `AppContext.db_lock` で直列化（SQLite は `check_same_thread=False`）。

## 2. ディレクトリ構成（05 システム設計書のレイヤ分離に準拠）

```
app/
  config.py            設定（NFR-13：解錠秒数・タイムアウト・CSV書式等）
  db.py                SQLite 接続・スキーマ初期化
  context.py           依存組み立て（DIコンテナ相当）＋ db_lock
  domain/models.py     Member / Item / Loan と業務ルール
  repository/          MEMBER / ITEM / LOAN へのアクセス
  devices/             カード・ロックの抽象化
    base.py            インタフェース
    mock.py            開発機・テスト用モック
    nfc_reader.py      実機: RC-S380 / nfcpy（FR-01, CON-4 IDmのみ）
    gpio_lock.py       実機: GPIO / gpiozero（FR-05, NFR-08 数秒通電→OFF）
    factory.py         Pi 自動判定でモック/実機を選択
  services/            auth / loan / member / report / clock（ユースケース）
  web/
    terminal.py        サーバ側状態機械（画面遷移の一元管理）
    server.py          http.server + SSE + /api/action
    templates/index.html
    static/app.js      SSEを受けて描画する薄いクライアント
    static/style.css   タッチ向けスタイル（800x480）
schema.sql             DDL（06 データベース設計書）
config.json            設定ファイル
main.py                エントリポイント
```

## 3. 実行（開発機 / Windows）

```bash
python main.py --seed     # デモメンバー投入 + Webサーバ起動
# ブラウザで http://127.0.0.1:8000/ を開く
```

モックモードでは画面下に「疑似タッチ」バーが出る（カード＝ボタン、解錠＝コンソール出力）。

## 4. 実行（Raspberry Pi 4 実機）

```bash
sudo apt install chromium-browser     # キオスク表示用
pip install nfcpy gpiozero            # 実機デバイス
python main.py --seed                 # サーバ起動（127.0.0.1:8000）
chromium-browser --kiosk --noerrdialogs --disable-infobars http://localhost:8000/
```

- `config.json` の `card_reader` / `lock` を `"auto"` のままにすれば、Pi 上では自動で
  RC-S380(nfcpy) と GPIO(gpiozero) を使う（`"mock"` / `"real"` で明示指定も可）。
- OS 起動時の自動起動は、サーバ（systemd サービス）とキオスク（autostart で Chromium）に分けて設定する。

| 設定キー | 意味 |
|----------|------|
| `lock_gpio_pin` | 駆動回路へつなぐ GPIO 番号（既定 17 / BCM） |
| `lock_active_high` | 駆動回路の論理（HIGHで通電=解錠 なら true） |
| `unlock_seconds` | 解錠通電時間（FR-05 / NFR-08） |
| `idle_timeout_seconds` | 無操作で待受画面へ復帰（NFR-06） |
| `require_tap_to_start` | true=最初に「画面にタッチしてはじめる」待受(attract)を挟む / false=直接カード待ち(standby) |

> ハードは **LE-53＝通電時解錠**、GPIO→駆動回路（MOSFET or リレー＋還流ダイオード）→ソレノイド。
> 詳細配線は [`../09_ハードウェア設計書.md`](../09_ハードウェア設計書.md)。
> localhost 限定のため外部公開はしない（キオスク専用）。

## 5. HTTP インタフェース

| メソッド/パス | 用途 |
|---------------|------|
| `GET /` | キオスク画面（index.html） |
| `GET /events` | SSE。画面状態を push（接続直後に現在状態も送る） |
| `GET /api/state` | 現在の画面状態（フォールバック） |
| `GET /api/meta` | 物品名・モック判定・（モック時）疑似タッチ用メンバー一覧 |
| `POST /api/action` | 操作（`{"type": ...}`）。`register_member`/`export_report` は結果を返す |

`POST /api/action` の `type`: `start`（attract→standby） / `choose_duration` / `confirm_return` / `cancel` /
`admin_menu` / `open_member_admin` / `open_report` / `admin_self_borrow` /
`register_member` / `set_member_active` / `export_report` /（モック時）`dev_card`。

## 6. 要件トレース

| 要件 | 実装 |
|------|------|
| FR-01 社員証認証 | `services/auth.py`・IDm照合（未登録/無効は拒否） |
| FR-02 貸出 | `services/loan.py` borrow（空き判定 CON-3・due算出・解錠） |
| FR-03 返却 | `loan.py` return_loan（本人判定・[10]Q6 設定で切替） |
| FR-04/09 状況・延滞 | `loan.py` status / `Loan.is_overdue` → 待機画面表示 |
| FR-05 解錠制御 | `devices/gpio_lock.py`（数秒ON→必ずOFF・連打抑止 NFR-08） |
| FR-06 メンバー管理 | `services/member.py` + メンバー管理画面 |
| FR-07 ログCSV出力 | `services/report.py`（帳票同項目・`YYYY/MM/DD hh:mm`） |
| FR-08 管理者認証 | role=admin で管理メニューへ |
| NFR-06 無操作復帰 | `web/terminal.py` のアイドルタイマ |
| NFR-07 2秒以内 | SSE push（ポーリングなし） |
| NFR-13 設定変更 | `config.json` |
